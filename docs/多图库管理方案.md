# 多图库管理 · 施工方案

> 目标：让「月相」能管住多个图库——启动能看到全部、运行时两秒切换、换个目录也认得出是哪个库。
> 现状：已经支持开多个库（不同目录各一份 `library.db`），但**没有列表**，每次切换要回到欢迎页重新翻文件夹。
> 改动范围：`config` 加字段 + `meta` 表用起来 + 三个界面。**不动任何现有的库读写逻辑。**

---

## 0. 现在是什么样

```
点「切换图库」→ setLibrary(null) → 回到 Welcome 页
              → 点「打开已有」→ 系统选目录弹窗 → 逐层翻找 → 打开
```

痛点三个：

1. 不记得自己有几个库、都在哪
2. 切库要重新浏览目录，过程 15 秒以上
3. 目录一改名/移动，就彻底认不出来了

---

## 1. 数据结构

### 1.1 `config.json` 加两个字段

```ts
export interface LibraryEntry {
  /** UUID，存在 library.db 的 meta 表里；目录改名/移动后仍能认回同一个库 */
  id: string
  path: string
  name: string
  lastOpened: number
  /** 上次打开时的张数，用于卡片展示；打开时刷新 */
  itemCount: number
}

export interface AppConfig {
  // …现有字段保持不变…
  library?: string                        // 保留：上次打开的库，兼容老数据
  libraryIndex?: Record<string, string>   // 保留：库路径 → 索引目录

  // 新增
  libraries?: LibraryEntry[]
}
```

⚠️ **`library` 字段不要删**。`library:last` 的启动恢复逻辑依赖它，删了要改一片。让两个字段并存，`libraries` 只是"清单"，`library` 仍然是"当前/上次"。

### 1.2 `library.db` 里写 ID

`meta` 表现在是空的 key-value 表，正好用：

```sql
INSERT OR IGNORE INTO meta(key, value) VALUES ('library_id', '<uuid>');
```

读取：

```ts
function readOrCreateLibraryId(dir: string): string {
  const db = /* 打开该库的 library.db */
  const row = db.prepare("SELECT value FROM meta WHERE key = 'library_id'").get()
  if (row) return row.value
  const id = randomUUID()
  db.prepare("INSERT INTO meta(key, value) VALUES ('library_id', ?)").run(id)
  return id
}
```

**为什么值得多这一道**：用路径当身份，用户把 `E:\照片` 改名成 `E:\照片2026`，注册表就多出一条"找不到的库"，用户还以为数据丢了。有了 UUID，重新定位后能认出来是同一个。

## 2. 老用户迁移（零感知）

启动时读 config，如果 `libraries` 不存在但 `library` 有值：

```ts
function ensureLibraries(config: AppConfig): AppConfig {
  if (config.libraries?.length) return config
  if (!config.library) return { ...config, libraries: [] }
  return {
    ...config,
    libraries: [{
      id: readOrCreateLibraryId(config.library),   // 首次会写进该库的 meta
      path: config.library,
      name: basename(config.library),
      lastOpened: Date.now(),
      itemCount: countItems(config.library)
    }]
  }
}
```

放在 `readConfig()` 里做不合适（每次读都写盘），建议放在**应用启动时调一次**。

## 3. 主进程：新增 `src/main/libraries.ts`

```ts
export function listLibraries(): Array<LibraryEntry & { missing: boolean }>
export function touchLibrary(dir: string): void              // 打开库时更新 lastOpened + itemCount
export function renameLibrary(id: string, name: string): void
export function forgetLibrary(id: string, alsoDeleteData: boolean): void
```

### 3.1 `listLibraries` 要顺手探活

```ts
// 每条都检查目录和 library.db 还在不在，不在就标 missing
const missing = !existsSync(entry.path) || !existsSync(join(resolveIndexDir(entry.path), 'library.db'))
```

界面拿到 `missing: true` 就显示灰色的"目录不见了"，而不是让人打开后报错。

### 3.2 `touchLibrary` 挂在哪

现有 `library:open` 里已经有 `updateConfig({ library: dir })`，紧跟着加一行：

```ts
ipcMain.handle('library:open', async (_e, dir) => {
  // …现有逻辑…
  updateConfig({ library: dir })
  touchLibrary(dir)          // ← 新增：刷新注册表里的这条
  restartWatcher()
  return dir
})
```

`itemCount` 就在 `touchLibrary` 里查一次 `SELECT COUNT(*) FROM items WHERE trashed = 0`。

### 3.3 `forgetLibrary` 的两种语义

```ts
forgetLibrary(id, alsoDeleteData = false)
```

- `false`（默认）：只从清单移除，**磁盘上的库原封不动**
- `true`：连目录一起删

⚠️ 界面上的措辞必须区分清楚，`true` 那条要二次确认，并且明确写出「会删除 N 张照片的索引，原图文件不动」。**永远不删原图**，只删 `library.db` / `thumbnails` / `previews`。

## 4. IPC

沿用现有命名风格（`library:*` 单数已占用，新的用 `libraries:*`）：

```ts
ipcMain.handle('libraries:list', () => listLibraries())
ipcMain.handle('libraries:rename', (_e, id: string, name: string) => renameLibrary(id, name))
ipcMain.handle('libraries:forget', (_e, id: string, alsoDeleteData: boolean) =>
  forgetLibrary(id, alsoDeleteData))
ipcMain.handle('libraries:relocate', async (_e, id: string) => {
  // 弹目录选择框 → 读新目录的 library_id → 和 id 对上才更新路径
  // 对不上就明确告诉用户「这个目录不是原来的那个库」
  return relocateLibrary(id)
})
```

`libraries:relocate` 是解决"目录搬家"的关键，逻辑是：

```
选一个新目录 → 读它的 library.db 里的 library_id
  ├─ 和要找回的 id 一致 → 更新 path，成功
  ├─ 那个目录没有 library.db → 提示「这里没有图库」
  └─ id 不一致 → 提示「这是另一个库（叫 xxx），不是要找的那个」
```

## 5. 渲染层：三个界面

### 5.1 启动页改成图库卡片墙（`Welcome.tsx`）

有库的时候：

```
┌──────────┐ ┌──────────┐ ┌──────────┐
│  ▢ 照    │ │  ▢ 小    │ │    +     │
│  照片     │ │ 小林1104  │ │  新建图库 │
│ 31894 张  │ │ 428 张    │ │          │
│ 3 天前    │ │ 昨天      │ │  打开已有 │
└──────────┘ └──────────┘ └──────────┘
```

- 封面 P1 先用**色块 + 首字**（像 Notion 的默认封面）。想用真缩略图得等库打开过、缓存到全局位置才行，那是 P2 的事。
- 卡片右上角 `⋯` 菜单：重命名 / 重新定位 / 从列表移除
- `missing` 的库卡片压暗，底部一行红字「目录不见了」+「重新定位」

### 5.2 运行时切换面板（新增 `LibrarySwitcher.tsx`）

点侧栏那个「切换图库」按钮 → **原地弹面板**，不再回欢迎页：

- 列表 + 搜索框（库多的时候有用）
- 键盘上下选，回车切换
- 底部一行「+ 打开其他图库…」

切换流程保持在主进程 `library:open`（现在就是它），渲染层只需要在切完后重新拉一次数据。**不用 reload 窗口**，现在 `openLibrary` + `regroup` 那套已经能热切。

### 5.3 侧栏加库名

现在侧栏顶部显示的是文件夹名。多库之后建议显示 `库名 › 当前文件夹`，让人随时知道自己在哪个库里。

## 6. 施工步骤

| # | 改哪里 | 做什么 | 怎么验证 |
| --- | --- | --- | --- |
| 1 | `db.ts` | 建库时写 `library_id` 到 meta | 新库打开后，`SELECT * FROM meta` 有值 |
| 2 | `settings.ts` | `AppConfig` 加 `libraries` 字段 | typecheck 过 |
| 3 | 新增 `libraries.ts` | `listLibraries` / `touchLibrary` / `rename` / `forget` | 直接调函数验证返回结构 |
| 4 | 启动迁移 | 老 `library` 包成一条 `libraries` | 用现有 config 启动，注册表里出现"照片"这条 |
| 5 | `ipc.ts` | `library:open` 里加 `touchLibrary`；注册 4 个 `libraries:*` | 切一次库，`lastOpened` 更新时间变了 |
| 6 | `Welcome.tsx` | 加卡片墙（保留原有新建/打开） | 有库时显示卡片，没库时和现在一样 |
| 7 | 新建 `LibrarySwitcher.tsx` | 切换面板 | 点按钮弹面板，选中能切过去，数据正确刷新 |
| 8 | `Sidebar` + `App.tsx` | `onSwitch` 改成开面板；顶部显示库名 | 切库两秒内完成，不闪白 |

**第 4 步要特别小心**：迁移只跑一次，跑完立刻写回 config。不要每次读 config 都算一遍 UUID —— 那样如果两个库的 meta 都没写过，可能会写出不一致的 id。

## 7. 边界情况

| 情况 | 处理 |
| --- | --- |
| 库目录被删 | 卡片显示「目录不见了」，只能移除或重新定位 |
| 库目录被改名 | 同上，走「重新定位」能认回（靠 UUID） |
| 用户手动把 library.db 删了 | 显示「索引丢失」，提示可以重建（原图还在） |
| 两个库指向同一目录 | 按 path 去重，只留一条 |
| 库数量很多（>20） | 卡片墙滚动 + 搜索；这时更该考虑是不是分得太碎了 |
| 库在移动硬盘上，盘没插 | 同「目录不见了」，但提示措辞改成「所在磁盘未连接」 |

## 8. 明确不做的事

**跨库搜索**
每个库独立 FTS，跨库要逐个查，而且搜到了还得切库。投入产出不划算。

轻量替代：当前库搜不到时，底部一句「其他 2 个库里可能还有 15 条 →」，点了才去查。

**多开窗口**
两个窗口共用一份 `config.json` 会互相覆盖；同一个库多开还有 db 锁风险。切换已经够快，不值得引入并发问题。

---

## 9. 验收标准

- [ ] 启动能看到所有图库，卡片带张数和最后打开时间
- [ ] 点卡片直接进库，不用再选目录
- [ ] 运行中点切换面板，两秒内切完，不闪白、不丢选中状态
- [ ] 库目录改名后，「重新定位」能认回同一个库（数据完好）
- [ ] 「从列表移除」不会删磁盘上任何东西
- [ ] 删除数据那条有二次确认，且明确写「原图不动」
- [ ] 老用户升级后，原来的库自动出现在列表里，不需要任何操作
- [ ] 只有一个库的用户，体验和现在完全一样（卡片墙不打扰）

最后一条是底线：**多图库是给需要的人用的，单库用户不该感受到任何变化。**

## 10. 附：什么时候该分库

| 分库的代价 | 分库的收益 |
| --- | --- |
| 找不到（不确定在哪） | 客户隔离，交付不怕搞混 |
| 来回切，心流断 | 可以单独归档 / 单独删 |
| 标签体系各建一遍 | 单库备份更小更快 |
| 跨库统计做不了 | — |

**建议：按「交付物」分，不按「类型」分。**

- 主库（日常素材、练习片、参考图）保持不动
- 新接的单一单一库，交付完直接归档
- 参考图不要单独建库，用 `reference` 标记 + facet 区分就够

控制在 10 个库以内，既隔离了客户数据，又不会把自己绕进去。
