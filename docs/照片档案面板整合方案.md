# 照片档案面板整合方案（PhotoInspector）

> 目标：把散在主图库详情面板、人像工作台右栏、以及未来的研读功能里的信息，收进**同一个组件**，按 Tab 分区。
> 收益：一套 UI、三个入口、各自默认到最常用的那个 Tab。以后加功能往对应 Tab 里塞，面板不会无限长。
> 状态：施工方案，按 §6 顺序改。

---

## 0. 为什么要先做这一步

如果不先统一，研读会变成**第四个独立入口**。等以后想整合，还得再搬一次家。先把架子搭好，研读直接长在第四个 Tab 里，一步到位。

## 1. 现状

### 1.1 `DetailPanel.tsx`（498 行，9 个区块，15 个 props）

| 行号 | 区块 | 性质 |
| --- | --- | --- |
| 264 | 标签 | 归类 |
| 304 | 文件夹 | 归类 |
| 354 | 文件信息 | 客观 |
| 362 | AI 评分 | 评价 |
| 417 | 分组（连拍/堆叠） | 归类 |
| 438 | 拍摄参数 | 客观 |
| 449 | 主色 | 客观 |
| 464 | 备注 | 主观 |
| 474 | 位置（文件路径） | 客观 |

Props 里混了三类东西：数据（`item` / `tags` / `folders`）、回调（`onRefresh` / `onPushUndo` / `onUnstack` / `onFindSimilar` / `onAdvice` / `onScore`）、开关（`aiReady` / `canScore` / `canAdvice` / `aiScoring`）。

### 1.2 人像工作台右栏

`PortraitWorkspace.tsx` 里自己实现了一套 facet 编辑（`assignedValues` / `applyValue` / `addValue`，约 120 行），和 `DetailPanel` 完全独立。

### 1.3 灯箱

`Lightbox.tsx` 目前没有任何信息侧栏。

**问题**：同一张照片，主图库看得见评分和备注、工作台看得见分类、灯箱什么都看不见。用户得在三个地方来回跳。

## 2. 目标结构：四个 Tab

```
PhotoInspector
├── 信息     EXIF · 拍摄参数 · 主色 · 位置 · 标签 · 备注
├── 分类     9 个 facet 维度（景别/视角/光线/天气/场景/色调/氛围/情绪/时段）
├── 表现     AI 评分 · 后期建议
└── 研读     圈选提问 · 追问 · 笔记（P1 后期接入）
```

**为什么是四个而不是三个**：把「客观属性」和「主观归类」分开，是因为它们的使用节奏完全不同——信息是查的时候看，分类是打标的时候连着点十几个。混在一个 Tab 里会互相干扰。

### 默认 Tab 按宿主决定

| 宿主 | 默认 Tab | 理由 |
| --- | --- | --- |
| 主图库 | 信息 | 平时是"查这张是什么" |
| 人像工作台 | 分类 | 进来就是为了打标 |
| 灯箱 | 研读 | 看大图就是为了读片 |

同一个组件，三个入口，各自落到最常用的位置。

### Tab 记忆

用 `localStorage` 记住每个宿主的**最后一次** Tab，不要每次重置。key 建议 `lunaris:inspector:tab:<host>`。

## 3. 组件拆分

### 3.1 目录

```
src/renderer/src/components/inspector/
├── PhotoInspector.tsx        外壳：Tab 栏 + 内容区 + 折叠逻辑
├── InfoTab.tsx               信息
├── FacetTab.tsx              分类（从 PortraitWorkspace 抽出来）
├── PerfTab.tsx               表现（AI 评分 + 后期建议）
└── StudyTab.tsx              研读（P1 后期接入，先留占位）
```

### 3.2 外壳接口

```ts
export type InspectorTab = 'info' | 'facet' | 'perf' | 'study'
export type InspectorHost = 'library' | 'portrait' | 'lightbox'

interface PhotoInspectorProps {
  item: Item
  host: InspectorHost
  /** 不传就用 host 的默认值 */
  defaultTab?: InspectorTab
  /** 窄屏 / 灯箱内嵌时收窄内边距 */
  compact?: boolean
  onClose?: () => void
  /** 各 Tab 的可见性由宿主决定，比如 noAi 时 perf 直接不出现 */
  available?: Partial<Record<InspectorTab, boolean>>
  children?: never
}
```

**关键设计**：`available` 控制 Tab 显隐而不是让 Tab 内部显示"未启用"。这样 AI 没开的时候，`表现` Tab 整个不存在——和现有产品原则「关掉就不显示」一致，不用灰按钮占位。

### 3.3 每个 Tab 的数据来源

不要把所有 props 一路透传。建议每个 Tab 自己去拿数据：

| Tab | 数据来源 | 说明 |
| --- | --- | --- |
| Info | props 传 `item` / `tags` / `folders` | 宿主已经有了，直接传 |
| Facet | `window.api.listFacets()` 自取 | 全局数据，缓存一份即可，不必让宿主操心 |
| Perf | props 传 `item.quality` + 回调 | 评分要触发 AI 调用，回调必须由宿主控制成本 |
| Study | `window.api.notes.list(itemId)` 自取 | 按张拉取，简单 |

**原则**：全局数据（facet 列表）自己取，和宿主强相关的东西（评分回调、撤销栈）走 props。

## 4. 三个宿主怎么接

### 4.1 主图库（`App.tsx` + `DetailPanel`）

`DetailPanel.tsx` 保留为**薄壳**，内部换成 `<PhotoInspector host="library" />`，原有 props 原样透传。

这样 `App.tsx` 一行都不用改，风险最低。

### 4.2 人像工作台（`PortraitWorkspace.tsx`）

现在右栏那 120 行 facet 逻辑搬进 `FacetTab.tsx`，工作台右栏换成 `<PhotoInspector host="portrait" compact />`。

⚠️ 注意：工作台的 facet 逻辑比 `DetailPanel` 里的复杂（支持多选、批量作用到选中项、新建取值）。搬的时候要**原样搬**，别顺手"优化"，否则行为会变。

### 4.3 灯箱（`Lightbox.tsx`）

新增一个可折叠侧栏，默认收起。展开时渲染 `<PhotoInspector host="lightbox" compact />`。

这一块和研读面板是同一个位置——P1 接入研读时，`StudyTab` 直接填进去，不用再动灯箱布局。

---

## 5. 两个必须处理的细节

### 5.1 评分要挪出「信息」，但不是删掉

现在 `AI 评分` 嵌在文件信息里（行 362 嵌套在行 354 内）。搬进 `表现` Tab 后：

- 信息 Tab 里不再出现评分
- 表现 Tab 顶部显示分数 + 四维条形 + 评语
- 「重新评分」按钮保留，但**加一句成本提示**（现有交互规范里已有）

### 5.2 备注改名，避免和研读笔记混淆

`Section title="备注"` 改成 **「备注 · 用途」**，placeholder 改成「客户要求、这张给谁用、拍摄备忘…」。

研读笔记叫「研读」，两者数据不合并，但在信息 Tab 底部加一行：

> 有 3 条研读笔记 →

点了跳到研读 Tab。用户就不会问"该写哪"。

## 6. 施工步骤

| # | 改哪里 | 做什么 | 怎么验证 |
| --- | --- | --- | --- |
| 1 | 新建 `inspector/PhotoInspector.tsx` | 只做 Tab 栏 + 空内容区 | 三个 Tab 能点能切，切换有记忆 |

| 3 | 新建 `PerfTab.tsx` | 搬 362 的 AI 评分 + 后期建议入口 | 评分按钮调用成功，评语正常显示 |
| 4 | 改 `DetailPanel.tsx` | 换成薄壳，包一层 `PhotoInspector` | 主图库整体回归：无报错、无明显布局变化 |
| 5 | 新建 `FacetTab.tsx` | 从 `PortraitWorkspace` 原样搬 facet 逻辑 | 多选、批量作用、新建取值三个行为都不变 |

## 7. 风险

| 风险 | 应对 |
| --- | --- |
| 搬 facet 逻辑时"顺手优化"导致行为变 | 原样搬，一行不改，跑通之后再考虑整理 |
| `DetailPanel` 的 15 个 props 一路透传变成面条 | Tab 内部自取全局数据，只让强相关的走 props |
| 灯箱侧栏挤掉图片 | 默认收起，展开时图片区 `flex-1` 自适应，和研读方案同一套逻辑 |
| 四个 Tab 在 320px 宽里挤不下 | Tab 用图标 + 短标签；窄屏时只显示图标，hover 出全名 |
| 以后再加 Tab 又变长 | 新功能优先往已有四个 Tab 里加分区，不轻易开第五个 |

## 8. 验收标准

- [ ] 主图库、人像工作台、灯箱三处打开的是同一个组件（视觉与行为一致）
