# 客户选片页 · 方案

> 目标：把「发微信 + 客户对着聊天记录说第几张」变成「发一个网页 + 客户点一点 + 复制一段文字发回来」。
> 形态：导出一个**自包含 HTML**，客户双击就能开，不需要装软件、不需要联网、不需要注册。
> 可玩原型：`design/photo-pick-page.html`（18 张真实照片，文件 388 KB，可以直接点）

---

## 0. 为什么这个功能最值钱

现在 app 的**前半程做得很细**：RAW 配对、连拍堆叠、语义搜图、9 个分类维度、AI 评分。比不少商业软件都全。

但**后半程是空的**：选片、交付。

而客户不为"整理得好"付钱，只为"片子交到我手上"付钱。

这一步是把前面所有功能变成收入的关键——之前都停在"自己看着爽"。

---

## 1. 客户看到什么

打开就是相册，18 张一屏能扫完：

```
┌──────────────────────────────────┐
│ SELECTED FOR YOU                  │
│ 小林 · 老门东街拍                   │
│ 王女士，这一组共 18 张，选您喜欢的就行  │
│ ▬▬▬▬▬▬▬▭▭▭▭▭▭▭▭▭▭▭▭             │
│ 已选 2   待修 1   已排除 1          │
├──────────────────────────────────┤
│ [001 ✓]  [002 ✎]  [003]  [004 ×]  │
│ [005]    [006]    [007]  [008]    │
│           ⋮                       │
├──────────────────────────────────┤
│      生成选片清单（3 张）            │
└──────────────────────────────────┘
```

每张照片右下有三个按钮：**要 / 要修 / 不要**。
- 选了「要」→ 绿色描边 + 勾
- 「要修」→ 橙色描边 + 铅笔
- 「不要」→ 变灰
- 顶部实时显示进度，底部按钮一直告诉你还差多少

选完点底部，弹出一段文字，客户复制粘贴发给主人即可。

## 2. 五个关键决策

### 2.1 交付形态：单个自包含 HTML

| 方案 | 问题 |
| --- | --- |
| zip 包 | 客户要解压，长辈搞不定 |
| 网盘链接 | 要注册、要下载 App、链接会过期 |
| 在线站点 | 主人得维护服务器 |
| **单个 HTML** | **微信直接发文件，点开就能看，零门槛** ✅ |

图片 base64 内嵌。实测 18 张 / 388 KB，80 张约 1.7 MB，200 张约 4 MB——微信文件上限 100 MB，完全够。

### 2.2 水印：烘焙进图，不用 CSS 叠

CSS 叠的水印客户随手一查开发者工具就能去掉。用 sharp 把水印**合成进像素**再转 base64，是真的去不掉。

- 内容：客户名 + 日期，右下角半透明角标
- 主人才有原图，精修交付时才给无水印版

### 2.3 结果回传：一段可读的文本

不用 JSON、不用链接、不用账号。客户就粘贴一段话：

```
【选片结果】小林 · 老门东街拍
客户：王女士

要的（18 张）：
012, 015, 018, 023, 027, 031, 035, 041, 044,
048, 052, 056, 061, 065, 070, 073, 076, 080

要修的（3 张）：
015, 044, 070

不要的：其余
```

人看着像回事，机器一个正则就能解析。**这是整个方案里最省事的一环**——不需要任何网络设施。

### 2.4 编号：三位序号，不用文件名

客户念「015」比念「DSC_8842.NEF」清楚一百倍。

导出时建立 `003 → item_id 39296` 的映射存进库，主人导入结果时按序号反查。

### 2.5 客户看不到 EXIF，也下不到原图

只给压缩图（长边 1200 / q72），右键保存也是带水印的压缩图。拍摄参数一律不显示——客户不需要看，也没必要露怯。

## 3. 数据模型

```sql
CREATE TABLE IF NOT EXISTS pick_sessions (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  token        TEXT UNIQUE,          -- 8 位短码，方便主人在文件名里认出是哪一单
  title        TEXT NOT NULL,        -- '小林 · 老门东街拍'
  client       TEXT NOT NULL DEFAULT '',
  photo_count  INTEGER NOT NULL DEFAULT 0,
  watermark    TEXT NOT NULL DEFAULT '',
  created_at   INTEGER NOT NULL,
  sent_at      INTEGER,              -- 导出时间
  received_at  INTEGER               -- 导入客户结果的时间
);

-- 序号 ↔ 照片的映射，导出时写入，导入时反查
CREATE TABLE IF NOT EXISTS pick_items (
  session_id INTEGER NOT NULL,
  seq        INTEGER NOT NULL,       -- 1..999
  item_id    INTEGER NOT NULL,
  action     TEXT,                   -- keep | fix | reject | NULL
  note       TEXT,
  PRIMARY KEY (session_id, seq)
);
CREATE INDEX IF NOT EXISTS idx_pick_items_item ON pick_items(item_id);
```

⚠️ **不要用 `items.flag` 存客户选择**。旗标 P/X/U 是主人自己的判断，客户选片是另一层信息，混在一起以后分不清"这是我挑的还是客户挑的"。

筛选器加一个独立条件「客户已选」即可。

## 4. 主进程

新文件 `src/main/pick.ts`：

```ts
createSession(input: { itemIds: number[]; title: string; client: string; watermark: string }): PickSession
exportSession(sessionId: number, opts: { maxEdge: number; quality: number; outDir: string },
              onProgress: (done: number, total: number) => void): Promise<{ path: string; bytes: number }>
parseClientReply(text: string): { keep: number[]; fix: number[]; dropped: number }   // 返回序号
applyClientReply(sessionId: number, parsed): { keep: number; fix: number; unmatched: number[] }
listSessions(): PickSessionWithStats[]
getSessionItems(sessionId: number): Array<{ seq: number; itemId: number; action: string | null }>
```

### 4.1 导出流程

```
1. 校验：选中的照片数 ≤ 999（三位编号塞不下更多，实际也不会）
2. 逐张处理：读原图 → sharp resize(长边 1200) → 合成水印 → jpeg q72 → base64
3. 每 10 张回调一次进度，复用现有导入进度条那套 UI
4. 套 HTML 模板，注入 { title, client, items[] }
5. 写到 outDir/{title}-{token}.html
6. 顺手把 seq→item_id 映射写进 pick_items
```

**耗时估算**：200 张大约 40–60 秒（sharp 很快，瓶颈在 base64 编码）。必须放后台线程，不能阻塞主窗口。

### 4.2 导入流程

```ts
// 要容忍客户手动改动：中文逗号、换行、多余空格
const pickRe = /要的[（(]\s*(\d+)\s*张[）)][：:]\s*([\d\s,，、]+)/
const fixRe  = /要修的[（(]\s*(\d+)\s*张[）)][：:]\s*([\d\s,，、]+)/

const seqs = (m: RegExpMatchArray | null): number[] =>
  m ? m[2].split(/[,，、\s]+/).map(Number).filter((n) => n > 0) : []
```

解析完先给预览：「识别到 18 张要的、3 张要修，其中 2 个编号对不上」，确认后再落库。

### 4.3 水印合成

```ts
const label = `${client} · ${date}`
// 右下角，半透明白字 + 深色描边，保证在亮背景和暗背景上都看得清
```

字号按图片短边比例算（如 `shortEdge * 0.022`），太小看不清，太大毁画面。

## 5. 主人这边怎么用

### 5.1 导出入口

工具栏「生成选片页」（选中 ≥1 张时可用）。弹窗：

| 字段 | 默认值 |
| --- | --- |
| 标题 | 文件夹名 + 日期 |
| 客户名 | 上次用过的 |
| 水印 | 客户名 + 日期 |
| 图片长边 | 1200（可选 800 / 1200 / 1600） |
| 输出到 | 上次的目录 |

导出完提示：「已生成 `小林-老门东-7f3a.html`（1.7 MB），发给客户就行」+ 「打开所在文件夹」。

### 5.2 导入入口

工具栏「导入选片结果」→ 粘贴框 → 点「解析」→ 预览 → 「确认」。

预览要显示：
```
✓ 要的 18 张
✓ 要修 3 张
⚠ 2 个编号对不上（023、077），可能客户手改了
```

### 5.3 结果怎么用

落库后可做三件事：
1. 主图库筛选「客户已选」→ 只看客户点的那些
2. 一键「选中的加进文件夹 → 客户已选/小林1104」
3. 会话历史列表，能回看每一单客户选了什么

## 6. 边界情况

| 情况 | 处理 |
| --- | --- |
| 客户手机打不开 HTML | 同时导出一个"纯图片版"（无交互，只有带编号的大图列表），发这个兜底 |
| 文件超 20 MB | 自动分卷：`xxx-1of2.html`、`xxx-2of2.html`，客户分别选，清单分开生成 |
| 客户不会用 | 页面顶部一句话：「点照片下方的按钮告诉我您的想法，选完点最下面那个黑色按钮」 |
| 客户改主意 | 支持重新导入同一会话的结果，覆盖上一次（保留历史） |
| 客户只发截图不发文字 | 没法解析，但会话记录里能手动勾选 |
| 中途关掉页面 | `localStorage` 记着进度，重开还在 |

## 7. 分期

**P1（先做这个）**
- 建会话 + 导出 HTML（含水印）
- 客户三态选择 + 生成清单
- 导入解析 + 落库
- 筛选器加「客户已选」

**P2**
- 会话历史界面
- 多轮沟通（客户二次修改）
- 水印模板可调（位置、透明度、logo）
- 客户能在页面上写一句备注

**P3**
- 在线版（需要托管，主人得先有域名/对象存储）
- 客户选完自动回传（需要后端）

---

## 8. 验收标准

- [ ] 导出 100 张，耗时 < 60 秒，文件 < 8 MB
- [ ] 导出的 HTML 断网能正常打开，手机上能点
- [ ] 水印烘焙在像素里，右键另存还是带水印的
- [ ] 客户选完的文本，主人粘贴后编号全部对得上
- [ ] 客户中途关页面再打开，选择还在
- [ ] 不覆盖 `items.flag`，主人自己的旗标不受影响
- [ ] 导出失败（磁盘满、目录无权限）有明确提示，不静默

---

## 9. 和现在这条路的关系

```
拍 → 导入 → 整理 → 评价 → 【选片】 → 交付 → 沉淀
     ✓      ✓      ✓      新做      ↓
                              └→ 研读（学下一单怎么拍更好）
```

选片页做完，研读才有意义——因为「学得更好」最终要体现到「下一单交得更漂亮」上。

反过来，如果一直只做前半程，工具再精致也只是个私人收藏夹。
