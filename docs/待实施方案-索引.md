## 二、今晚的建议

**先只做一个：客户选片页。**

理由三条：

1. **最独立** —— 只加两张表、一个新文件、一个工具栏按钮，不改任何现有查询。改坏的概率最低。
2. **最快见效** —— 做完当天就能发给下一个客户用，不用等其它功能。
3. **补的是最缺的一环** —— 前半程（导入/整理/评价）已经很细了，后半程（选片/交付）是空的，而客户只为后半程付钱。

时间宽裕再加 **多图库**（也很独立）。**别一次开三个**，测不过来。

## 三、每个功能的"一句话核心"

免得重读文档：

### 客户选片页
导出一个**自包含 HTML**，客户双击就能点「要 / 要修 / 不要」，选完复制一段文字发回来，主人粘贴自动打标。
- 关键决策：单文件不走网盘 · 水印烘焙进像素 · 结果靠文本回传（不需要任何后端）
- 注意：**别用 `items.flag` 存客户选择**，单独建表，否则半年后分不清"客户要的"还是"我挑的"
- 可点原型：`design/photo-pick-page.html`

### 多图库管理
`config.json` 加 `libraries[]` 注册表，启动页变卡片墙，运行中原地弹切换面板。
- 关键决策：**库 ID 用 UUID 存 `meta` 表**（现在那张表是空的），目录改名后能认回来
- 注意：老 `library` 字段不能删，`library:last` 启动恢复还依赖它
- 底线：**单库用户不该感受到任何变化**

### XMP 侧车
把星级、旗标、标签、facet 写进照片旁的 `.xmp`，Lightroom / C1 / Bridge 都能读。
- 关键决策：**只写「人的判断」，不写 AI 评分等机器产物**
- 最赚的一点：facet 映射成 `lr:hierarchicalSubject: 景别|特写`，到 LR 里直接长成两级树
- 注意：默认关闭 · 标签里的 `&` 必须转义 · 写文件用原子替换
- 技术上：`exifr.sidecar()` 读，模板字符串写，**不用加依赖**

### 照片档案面板
把散在三处的信息收进一个 `PhotoInspector`，分四个 Tab（信息 / 分类 / 表现 / 研读）。
- 关键决策：**默认 Tab 按宿主决定**（主图库→信息，工作台→分类，灯箱→研读）
- 注意：搬 facet 逻辑时**原样搬，别顺手优化**，否则行为会悄悄变
- 先做这个，研读才有地方长

### 照片研读与复盘
灯箱里圈选 + 提问 + AI 反问（最多两轮必给答案）+ 研读/复盘双模式。
- 关键决策：**笔记锚定在画面区域**，不是飘在旁边的文本框
- 最容易翻车：圈选图层的坐标系（要复制 img 的定位样式，不能放外层 div）
- 底线：**AI 没配时，纯文字笔记必须还能用**

## 四、明确不做的事

今天讨论中被否掉的，别再捡回来：

| 想法 | 为什么不 | 
| --- | --- |
| facet 计数加缓存 / 计数器表 | **实测 0.1 ms**，给不存在的问题写代码，还会引入缓存不一致 |
| 跨库搜索 | 每库独立 FTS，跨库要逐个查，搜到了还得切库，投入产出不划算（改成"其他库可能还有 N 条"的提示） |
| 多开窗口 | 两个窗口共用 config 会互相覆盖，同库多开有 db 锁风险 |
| 研读笔记写进 XMP | 太长会撑大文件、拖慢 Lightroom |
| 用 `items.flag` 存客户选片 | 和主人自己的旗标混在一起，以后分不清 |
